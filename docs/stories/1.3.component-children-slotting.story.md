## Story

**As a** Zig UI developer,
**I want** to pass child elements into custom components via a slotting mechanism,
**so that** I can build reusable container components like cards, modals, and layouts that accept arbitrary content.

## Acceptance Criteria

1. `forbear.componentChildrenSlot()` marks the insertion point for children within a component's render function
2. A component can receive a block of child nodes via the composition API
3. Children are rendered at the correct position in the component's layout tree
4. Nested slotting works (component with slot inside component with slot)
5. A `Card` component in `playground.zig` demonstrates the slotting API with custom content passed in
6. `zig build test` and `zig build check` pass without errors

## Scope

**IN Scope:**
- Um único slot padrão por componente (`componentChildrenSlot()`)
- Mecanismo de passagem de children via chamada de `component()`
- Nested slotting (slot dentro de slot)
- Demo `Card` em `playground.zig`

**OUT of Scope:**
- Named slots (ex: `slot="header"`)
- Multi-slot (mais de um slot por componente)
- Slot com conteúdo padrão (fallback content)
- Slots condicionais / scoped slots

**Current Component API (from `src/node.zig` and `src/root.zig`):**

```zig

    id: usize,
    props: *anyopaque,
};

// Current usage pattern
try component(arenaAllocator, MyComponent, MyProps{...});
```

**Context state relevant to tree building (`src/root.zig`):**
- `frameNodeParentStack: std.ArrayList(*Node)` — current parent stack
- `frameNodePath: std.ArrayList(usize)` — position path in tree
- `previousPushedNode: ?*const Node` — last pushed node
- `rootNodes: std.ArrayList(Node)` — root nodes for current frame

**Design Consideration:**
The slotting mechanism needs to capture children before the component function runs, then inject them at the `componentChildrenSlot()` call site. One approach:
- Add a `pendingSlotChildren: ?std.ArrayList(Node)` field to Context
- Before calling component function, stash children in context
- `componentChildrenSlot()` reads from context and inserts children into current parent

**IMPORTANT — Spike Required:**
This story requires a design spike before implementation. The tree-building mechanism uses a stack-based approach that must be understood before adding slot injection. Review `element()` and `component()` functions fully in `src/root.zig` before writing any code.
