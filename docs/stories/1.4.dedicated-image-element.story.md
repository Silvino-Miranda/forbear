## Story

**As a** Zig UI developer,
**I want** a `forbear.image()` element that automatically sizes based on the image's aspect ratio,
**so that** I can display images naturally without manually calculating dimensions, and without frame drops during loading.

## Acceptance Criteria

1. `forbear.image(arena, imageId, style)` exists as a public function in the API
2. If only `width` or only `height` is specified in the style, the other dimension is automatically calculated from the image's aspect ratio
3. Large images (>1MB decompressed) do not cause visible frame drops (no >20fps drop for more than 1 frame)
4. `forbear.image()` supports `fit`, `fixed`, and `percentage` sizing for width and height independently
5. `Style.background = .{ .image = ... }` (backgroundImage) continues to work without any breaking change
6. A gallery demo in `playground.zig` demonstrates multiple images with correct aspect ratio sizing
7. `zig build test` and `zig build check` pass without errors

## Scope

**IN Scope:**
- Formatos PNG e JPEG via stb_image (já disponível no projeto)
- Async loading com estado atômico (`.loading` / `.ready` / `.failed`)
- Aspect ratio automático (query de header sem decode completo)
- Placeholder sólido durante carregamento
- `forbear.image()` com sizing: `fit`, `fixed`, `percentage`
- Demo gallery em `playground.zig`

**OUT of Scope:**
- GIF animado
- WebP, AVIF, BMP
- SVG (story separada no Epic 2)
- Lazy loading por viewport (scroll intersection)
- Cache de imagens decodificadas entre frames

## Dev Notes

**Architecture Decision (from `docs/architecture.md` — Section 4):**

Async loading uses **atomic state + worker thread** pattern:

```
Main thread: registerImage() → Image{state=.loading} → std.Thread.spawn(workerFn)
Worker:      stb_image decode → Vulkan upload → image.state.store(.ready, .release)
Render loop: image.state.load(.acquire) → render placeholder OR texture
```

**Current `Image` struct location:** `src/graphics.zig` (search for `pub const Image`)

**Current registration API (`src/root.zig` ~line 344):**
```zig
pub fn registerImage(uniqueIdentifier: []const u8, comptime contents: []const u8, format: Graphics.Image.Format) !void
pub fn useImage(uniqueIdentifier: []const u8) !*Image
```

**stb_image aspect ratio query:**
stb_image provides `stbi_info_from_memory()` which reads image dimensions from header without decoding pixels. Use this to set `aspectRatio` synchronously before spawning the decode thread.

**Background union (src/node.zig ~line 375) — DO NOT CHANGE:**
```zig
pub const Background = union(enum) {
    image: *Graphics.Image,
    color: Vec4,
};
```

**Vulkan thread safety concern:**
GPU texture upload from a non-render thread may require synchronization. Check if `Graphics.Renderer` has a transfer queue or if staging buffer uploads need a fence/semaphore. This is a potential blocker — investigate before implementing the worker thread's GPU upload step.

**Key Files:**
| File | Change Needed |
|---|---|
| `src/graphics.zig` | Extend `Image` struct with state/placeholder/aspectRatio, async decode |
| `src/root.zig` | Add `forbear.image()` function, aspect ratio logic |
| `playground.zig` | Add image gallery demo |
| `src/node.zig` | No changes needed |

**MVP simplification:** Use `std.Thread.spawn` per image (no thread pool). For the 10 showcase examples, image count is low enough that this is sufficient.
