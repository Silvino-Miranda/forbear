## Story

**As a** Zig UI developer,
**I want** to define element widths and heights as a percentage of their parent container,
**so that** I can build flexible layouts that adapt to parent size without hardcoding pixel values.

## Acceptance Criteria

1. `Style.width = .{ .percentage = 50 }` and `Style.height = .{ .percentage = 100 }` are valid, compilable Zig types
2. `resolvePercentageSizing()` correctly computes the absolute size before the final layout pass
3. Percentage is relative to the immediate parent's inner size (not the window/viewport)
4. Percentage sizing works correctly combined with `.grow`, `.fit`, and `.fixed` siblings in the same container
5. Unit tests cover: 50% of 200px parent = 100px, 100% = full parent size, nested percentages resolve correctly
6. `zig build test` passes with no errors

**Layout Pipeline Order (critical for correct integration):**
```
layout()
  ├── 1. buildLayoutBoxes()     ← creates LayoutBox tree from Node tree
  ├── 2. resolvePercentageSizing() ← NEW: resolve % before grow/shrink
  ├── 3. growAndShrink()        ← distributes remaining space
  ├── 4. wrap()                 ← text wrapping
  ├── 5. place()                ← assigns absolute positions
  └── 6. makeAbsolute()         ← converts relative to absolute coords
```

**Percentage Resolution Logic:**
- Inner parent size = `parent.size - parent.style.padding.x[0] - parent.style.padding.x[1]` (for width)
- `child.size[0] = parentInnerWidth * (percentage / 100.0)` for width
- Must handle direction: in `.leftToRight` container, percentage applies to width; in `.topToBottom`, to height
