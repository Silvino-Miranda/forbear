## Story

**As a** Zig UI developer,
**I want** to apply an underline decoration to text elements via a style property,
**so that** I can build links, emphasized text, and other underlined UI treatments.

## Acceptance Criteria

1. `Style.textDecoration = .underline` is a valid, compilable property
2. The underline is rendered correctly below the text baseline
3. The underline color follows the element's `Style.color` by default
4. Underline works correctly with variable fonts and different font sizes
5. `zig build test` and `zig build check` pass without errors

## Scope

**IN Scope:**
- `.underline` como único valor de `TextDecoration` além de `.none`
- Posicionamento abaixo da baseline do texto
- Cor = `Style.color` (mesma cor do texto)
- Espessura proporcional ao fontSize (`fontSize / 14.0`)
- Funciona com a variable font Inter e múltiplos tamanhos

**OUT of Scope:**
- `overline`, `strikethrough`, `line-through`
- Underline com cor customizada (separada da cor do texto)
- Underline ondulado, pontilhado, duplo
- Herança de `textDecoration` do elemento pai (não herda por design — per-element only)

```zig
    // ADD:

};
```

**BaseStyle struct (src/node.zig ~line 353):** Used for inherited style propagation.
Consider whether `textDecoration` should inherit from parent. CSS does inherit text-decoration.
For MVP simplicity, **do not inherit** — keep it per-element only.

**Rendering approach:**
The text rendering pipeline in `src/graphics.zig` draws glyphs from texture atlases. After the glyph rendering loop for a text `LayoutBox`, add a rect draw call:
```
underline_rect = Rect{
    .x = layoutBox.position[0],
    .y = layoutBox.position[1] + layoutBox.size[1] - underline_thickness - underline_gap,
    .width = layoutBox.size[0],
    .height = underline_thickness,
}
```

**Baseline position:** FreeType provides `metrics.ascender` and `metrics.descender` for each font. The descender (distance below baseline) can be used for precise underline placement. Alternatively, use `lineHeight * 0.85` as a simple approximation.

**This is the simplest story in Epic 1.** No architectural risks. Implement after 1.1 (which is already in progress). Good story to build confidence before tackling scrolling.
